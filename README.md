# Автономная система мониторинга окружающей среды

Станция на ESP32 (BME280, TDS/EC, GPS, DS3231, microSD, Battery Shield)
публикует измерения в MQTT. Сервер их принимает, хранит историю, сам
разбивает её по локациям и строит графики со сводкой по нормативам.
Через панель можно менять настройки станции и следить за связью.

```
ESP32 ──MQTT──> Mosquitto ──> мост в FastAPI ──> PostgreSQL
  ↑                │                                 │
  └── команды и настройки по подписке                 │
                                                      ↓
Браузер ──HTTPS──> Caddy ──> FastAPI ──> Svelte (статика)
```

## Структура

```
.
├── firmware/          прошивка ESP32 + INSTRUCTIONS.md (распиновка, библиотеки, ошибки)
├── mosquitto/         конфигурация брокера MQTT
├── backend/           FastAPI + SQLAlchemy (async) + PostgreSQL
├── frontend/          Svelte 5 + Vite, панель управления
├── docker-compose.yml профили prod и dev
├── Caddyfile          внешний реверс-прокси и TLS
└── .env.example       шаблон переменных окружения
```

Подробная инструкция по развёртыванию — в `DEPLOYMENT.md`, по железу и
прошивке — в `firmware/INSTRUCTIONS.md`.

## Запуск

```bash
cp .env.example .env
```

В `.env` обязательно поменять `POSTGRES_PASSWORD`, `JWT_SECRET`,
`ADMIN_PASSWORD`, `DEVICE_TOKEN` и `MQTT_PASSWORD`. С пустыми значениями
compose просто не стартует.

### Продакшен

```bash
docker compose --profile prod up -d --build
```

Поднимаются пять контейнеров: `db`, `mosquitto`, `api`, `web`, `caddy`.
Наружу смотрят только 80, 443 и 1883 (последний нужен станции), порт
PostgreSQL снаружи закрыт. Если в `SITE_ADDRESS` указан домен, Caddy сам
выпустит сертификат Let's Encrypt и будет его продлевать.

Панель открывается по адресу из `SITE_ADDRESS`, Swagger лежит на `/api/docs`.

### Разработка

```bash
docker compose --profile dev up --build
```

| Что | Где |
|---|---|
| панель с горячей перезагрузкой | http://localhost:5173 |
| API с автоперезапуском | http://localhost:8000/api/docs |
| PostgreSQL наружу | `localhost:5432` |

Исходники `backend/app` и `frontend/src` смонтированы томами, так что
правки подхватываются без пересборки. Caddy в dev не участвует: Vite сам
проксирует `/api` в контейнер бэкенда. Поэтому во фронтенде везде
относительные пути, и разницы между режимами в коде нет.

Профили не пересекаются, prod-сервисы в dev не поднимаются. Общий у них
только том `pgdata`, так что данные при переключении режима не теряются.

## Обмен со станцией

Основной транспорт — MQTT, брокер Mosquitto с авторизацией по паролю.
Дерево топиков:

| Топик | Направление | Назначение |
|---|---|---|
| `env/<id>/telemetry` | станция → сервер | живой замер, одно сообщение на запись |
| `env/<id>/backlog` | станция → сервер | выгрузка буфера SD, помечается историей |
| `env/<id>/status` | станция → сервер | retained, он же последняя воля |
| `env/<id>/log` | станция → сервер | события и ошибки |
| `env/<id>/ack` | станция → сервер | подтверждение выполнения команды |
| `env/<id>/cmd` | сервер → станция | команды панели |
| `env/<id>/settings` | сервер → станция | retained, актуальный конфиг |

Сервер подписан на `env/+/#`, так что новые станции подхватываются без
перезапуска.

Несколько решений, которые стоит пояснить.

Команды уходят в топик, на который станция подписана, поэтому доходят
сразу, а не в начале следующего цикла. Ради этого и делался переход с
HTTP на MQTT.

Топик `status` публикуется с флагом retained и одновременно назначен
последней волей. Панель видит состояние станции сразу при открытии, а
если станция пропадает, брокер сам публикует `{"online": false}` через
один keepalive. Ждать таймаута на сервере не нужно.

Настройки тоже retained: станция получает конфиг в момент подключения,
даже если сервер в это время перезапускается. Номер версии `rev` не даёт
применить один и тот же конфиг дважды.

А вот команды отправляются без retain, иначе станция выполняла бы их
заново при каждом переподключении. Если команду не удалось доставить,
она ждёт в БД и уходит при следующем статусе станции.

PubSubClient умеет только QoS 0, поэтому от дублей защищает не протокол,
а сам сервер: записи различаются по паре `(boot, seq)`, то есть по
идентификатору сеанса работы и номеру замера.

Резервный путь по HTTP (`POST /api/v1/ingest` с заголовком
`X-Device-Token`) оставлен для отладки без станции и на случай, когда
брокер недоступен. Разбор данных у обоих путей общий, он лежит в
`backend/app/ingest_service.py`.

## Защита от случайного действия

Опасные действия подтверждаются трижды, в трёх разных местах:

1. Панель показывает диалог со списком того, что именно меняется.
2. Сервер отвечает `409 confirmation_required` на отключение подсистемы,
   увеличение интервалов и на команды `reboot`, `clear_spool`,
   `factory_reset`.
3. Прошивка отдельно требует в сообщении `"confirm": true`, так что
   запрос из сторонней утилиты в обход панели станцию не сломает.

Настройки применяются целиком. Если хотя бы одно значение вышло за
границы, отклоняется весь патч — частично применённых конфигов не бывает.

## Панель

Тёмная тема: холодная основа, зелёный акцент для нормы, янтарный для
превышений. Логика как у лабораторного прибора, холодное означает
рабочее состояние, тёплое — тревогу.

Что важно в вёрстке:

- Управляющие элементы (сайдбар, верхняя панель, вкладки, полоса
  вердикта) сделаны полупрозрачными с размытием подложки, а карточки с
  данными плотные. Уровень важности задаётся глубиной, а не яркостью.
- Навигация на каждом экране ровно одна: до 900 пикселей нижние вкладки,
  от 900 сайдбар. Бургера и выезжающих панелей нет.
- Учитываются системные настройки: `prefers-reduced-transparency`
  заменяет стекло плотным фоном, `prefers-reduced-motion` выключает
  анимации, `prefers-contrast: more` усиливает границы.
- Вёрстка mobile-first, базовые правила описывают узкий экран, а
  медиазапросы только добавляют возможности широкого.

Шрифт Manrope с табличными цифрами, чтобы значения не прыгали при
обновлении. Иконки — контурный SVG на сетке 24.

Разделы:

- **Сводка** — вердикт по нормативам с индексом, текущие показания со
  шкалой допустимого диапазона, состояние датчиков, быстрые команды.
- **Графики** — по разделам либо объединённый с произвольным набором
  метрик. На графике минерализации проведена линия ПДК, обрыв связи
  рисуется разрывом линии.
- **Локации** — создаются сами из координат GPS, группируются по области.
- **Настройки** — переключатели подсистем отделены от калибровок.
- **Журнал** — события станции и действия операторов с указанием автора.

Графики написаны на голом SVG без библиотек, поэтому весь бандл
занимает около 106 КБ (40 КБ в gzip). Ширину они измеряют по контейнеру
и не рисуются до первого измерения: раньше начальная ширина была зашита
числом, и на телефоне график вылезал за экран.

## Как считается сводка

Пороги взяты из нормативов: СанПиН 1.2.3685-21 для минерализации воды,
ГОСТ 30494-2011 для микроклимата. Никакой статистики и обучения, просто
набор явных границ, поэтому любой вывод легко проверить и обосновать.
Сами пороги лежат в словаре `LIMITS` в `backend/app/analysis.py`.

Важная оговорка: этот набор датчиков меряет минерализацию воды и
микроклимат. Загрязнение воздуха (PM2.5, CO, NO₂) станция не измеряет, и
сводка об этом прямо пишет, вместо того чтобы выдавать правдоподобный
индекс из данных, которых нет. Для воздуха нужны газоанализаторы и
датчик пыли, это отдельная задача по железу.
