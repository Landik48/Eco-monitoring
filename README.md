# Автономная система мониторинга окружающей среды

Станция на ESP32 (BME280, TDS/EC, GPS, DS3231, microSD, Battery Shield)
шлёт замеры в MQTT. Сервер их принимает, хранит, разбивает по локациям и
строит графики со сводкой по нормативам. Через панель можно менять
настройки станции и следить за связью.

```
ESP32 ──MQTT──> Mosquitto ──> мост в FastAPI ──> PostgreSQL
  ↑                │                                 │
  └── команды и настройки по подписке                 │
                                                      ↓
Браузер ──HTTPS──> Caddy ──> FastAPI ──> Svelte (статика)
```

## Структура

```
firmware/          прошивка ESP32
  src/core/        логика без привязки к железу
  src/sensors/     по модулю на датчик
  src/net/         транспорт, телеметрия, команды, часы
  src/diag/        журнал
backend/           FastAPI + SQLAlchemy + PostgreSQL
frontend/          Svelte 5 + Vite
mosquitto/         конфиг брокера
docker-compose.yml профили prod и dev
Caddyfile          реверс-прокси и TLS
```

Развёртывание — `DEPLOYMENT.md`, железо и прошивка — `firmware/INSTRUCTIONS.md`.

## Запуск

```bash
cp .env.example .env
```

Обязательно поменять `POSTGRES_PASSWORD`, `JWT_SECRET`, `ADMIN_PASSWORD`,
`DEVICE_TOKEN`, `MQTT_PASSWORD`. С пустыми значениями compose не стартует.

```bash
docker compose --profile prod up -d --build   # прод
docker compose --profile dev up --build       # разработка
```

В dev поднимаются панель на 5173 с горячей перезагрузкой, API на 8000 и
PostgreSQL наружу на 5432. Исходники смонтированы томами, пересборка не
нужна. Caddy в dev не участвует, Vite сам проксирует `/api`.

Панель открывается по адресу из `SITE_ADDRESS`, Swagger на `/api/docs`.

## Топики MQTT

| Топик | Кто пишет | Что |
|---|---|---|
| `env/<id>/telemetry` | станция | замер |
| `env/<id>/backlog` | станция | выгрузка буфера SD |
| `env/<id>/status` | станция | retained, он же последняя воля |
| `env/<id>/log` | станция | события и ошибки |
| `env/<id>/ack` | станция | подтверждение команды |
| `env/<id>/timereq` | станция | запрос времени |
| `env/<id>/cmd` | сервер | команды панели |
| `env/<id>/settings` | сервер | retained, конфиг |
| `env/<id>/time` | сервер | ответ с временем, без retain |

Сервер подписан на `env/+/#`, новые станции подхватываются без перезапуска.

Что стоит держать в голове:

- `status` retained и одновременно последняя воля, поэтому офлайн виден
  через один keepalive, без таймаутов на сервере;
- `settings` retained, `rev` не даёт применить один конфиг дважды;
- команды без retain, иначе выполнялись бы заново при каждом коннекте;
  недоставленная ждёт в БД и уходит со следующим статусом;
- PubSubClient умеет только QoS 0, от дублей защищает пара `(boot, seq)`;
- API запускается в **один** воркер uvicorn: мост MQTT ходит к брокеру с
  фиксированным `client_id`, и два процесса выбивали бы друг друга. Если
  воркеров станет больше, мост надо выносить отдельно;
- запасной путь `POST /api/v1/ingest` с заголовком `X-Device-Token`
  оставлен для отладки без станции.

## Часы

Три источника, по убыванию точности: GPS (допуск 2 с), сервер (30 с),
RTC DS3231 (5 с). Точный источник правит менее точный всегда, обратное —
только если текущий молчит больше шести часов. Команда `set_time` из
панели обходит арбитраж.

Станция сама спрашивает время в `timereq`, сервер отвечает в `time` с тем
же `nonce`; по нему считается время оборота и компенсируется половина
задержки. Ответ без retain, иначе после простоя прилетало бы протухшее
время.

Между замерами время идёт от `millis()`. В DS3231 пишется не чаще раза в
час и с перечитыванием: на севшей батарейке микросхема принимает команду
и тут же забывает.

Без часов замеры всё равно уходят с `ts_valid: false`, сервер ставит им
время приёма.

## Контроль достоверности

Просадка питания заставляет датчики врать: температура скачет на десятки
градусов, TDS на сотни единиц. Задача — отсечь это, не потеряв настоящий
грозовой фронт.

Правила:

1. Быстрое изменение само по себе не брак. Замер бракуется, только если
   скачок совпал с просадкой напряжения или броском тока, либо если
   одновременно прыгнули несвязанные каналы (температура воздуха и
   минерализация воды вместе не меняются).
2. Скачок придерживается как кандидат. Если следующий замер держит новый
   уровень — изменение настоящее, станция шлёт `confirms_previous`, сервер
   помечает придержанный замер как `confirmed` и возвращает в расчёт.
   Подтверждать можно только при исправном питании: затяжная просадка
   тоже держит уровень и иначе прошла бы за фронт.

Забракованный замер всё равно отправляется — с флагом `suspect`, маской
причин и сырыми показаниями в `rejected`. В усреднение он не попадает,
иначе испортил бы `filter_size` следующих. В сводке и на графиках не
учитывается, но остаётся в БД и в выгрузке CSV.

Пороги настраиваются с сервера, раздел «Контроль достоверности».

## Подтверждение опасных действий

Три уровня: диалог в панели со списком изменений, ответ сервера
`409 confirmation_required` на отключение подсистем и команды `reboot`,
`clear_spool`, `factory_reset`, и требование `"confirm": true` в самой
прошивке. Настройки применяются целиком: одно значение вне границ —
отклоняется весь патч.

## Панель

Тёмная тема, зелёный акцент для нормы, янтарный для превышений.
Управляющие элементы полупрозрачные с размытием, карточки с данными
плотные. Навигация одна на экран: до 900 px нижние вкладки, дальше
сайдбар. Учитываются `prefers-reduced-transparency`, `prefers-reduced-motion`,
`prefers-contrast`. Вёрстка mobile-first.

Разделы: Сводка (вердикт с индексом, показания по группам воздух/вода/
питание, состояние датчиков, быстрые команды), Графики, Локации (создаются
сами из GPS), Настройки, Журнал.

Графики на голом SVG без библиотек, бандл около 115 КБ (43 КБ gzip).

## Как считается сводка

Пороги из нормативов: СанПиН 1.2.3685-21 для минерализации, ГОСТ
30494-2011 для микроклимата. Никакой статистики, только явные границы —
любой вывод можно проверить. Лежат в словаре `LIMITS` в
`backend/app/analysis.py`.

Давление и питание показываются, но общую оценку не определяют: циклон на
985 гПа это погода, а не превышение норматива.

Оговорка: этот набор датчиков меряет минерализацию воды и микроклимат.
Загрязнение воздуха (PM2.5, CO, NO₂) станция не измеряет, и сводка об
этом прямо пишет. Для воздуха нужны газоанализаторы и датчик пыли.
